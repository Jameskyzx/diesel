# 三角色模拟用户评估（非真实试点）

## 1. 评估边界

- 日期：2026-08-12。
- 对象：零配置作品 Demo 的首页、地图、国家详情、产品适配和 AI 对话，以及相关
  Repository、service、DTO 与测试。
- 角色：三个 subagent 分别模拟海外销售/区域销售用户、法规/合规工程师、
  产品/应用工程师。
- 方法：从第一次使用者视角完成代表任务，记录可见证据，再用只读代码与测试检查
  解释界面行为；发现 P0 后由主任务限定范围实施修复。

> 本轮是 AI subagent 的角色模拟，不是真实用户研究、客户试点、可用性实验或法规
> 专家签核。三名角色没有对应现实身份，未产生任务耗时、转化率、错误率、满意度或
> 复用率等 KPI；本文件不得被用来宣称产品市场验证、法律认可或商业效果。

## 2. 场景与证据

### 2.1 海外销售 / 区域销售用户

模拟任务：从地图选择国家，查看法规与市场资料，运行 Demo 产品适配；在出现
`unknown` 时判断下一步要补什么资料，并带着国家、scope、功率、日期和产品上下文
继续进入对话。

观察与反馈：

- Demo 卡片虽有多层虚构标识，但首屏的“明确匹配”仍可能被快速扫读成可报价、
  已认证或可作销售承诺；Demo 结果应降级为“演示匹配”，并在首屏直接禁止这些外推。
- `unknown` 的失败关闭是正确的，但缺口分散在多张证据卡中；销售用户需要一段可复制
  的补数摘要，交给产品、认证或法规同事继续处理。
- 从国家详情进入聊天时若丢失筛选条件，用户必须重述上下文，也更容易产生国家、日期
  或功率错配；跳转应携带完整已确认筛选。

### 2.2 法规 / 合规工程师

模拟任务：核对 `effective / adopted / proposed / superseded` 隔离，检查 `asOf`、
scope、功率半开边界、司法辖区与来源；打开一个 no-data 国家并判断页面是否暗示
“该国没有监管”；检查 covered、verified、stale 和 Demo 是否容易区分。

可复现证据：

- AFG no-data 页面明确写明“数据库尚未录入国家资料，系统不会用空白内容或模型推测
  代替事实”，没有把数据缺口描述成“无监管”。
- CHN Demo 产品 `[50,150)` kW 在 100 kW 通过、150 kW 不通过，半开区间表现符合
  规则；记录 ID、辖区成员期和来源可见。
- 修复前以 `asOf=2024-12-31` 查询 CHN 时，`adoptedOn=2026-01-10` 的 Stage C
  被显示为未来已采纳，形成未来知识泄漏；同一查询又遗漏了有效期为
  `[2020-01-01,2025-01-01)`、当前记录状态为 `superseded` 的 Stage Z。
- proposed 没有进入 effective 查询；但 covered、verified 和 stale 的产品内解释
  不如 README/STATUS 清楚，“已有结构化覆盖”或“已核验来源”可能被误读为四个 scope
  都有数值或已获得外部专家认可。

### 2.3 产品 / 应用工程师

模拟任务：输入产品、应用场景、功率与日期，检查适配边界、认证证据和法规追溯，
再判断能否快速把结果交给销售或合规同事。

观察与反馈：

- 确定性 fit、`not_fit`、`unknown` 三态和 `[min,max)` 边界是有价值的；缺少认证不会
  被自动解释成不合规。
- 原始证据默认全部展开、状态含英文枚举、数值保留数据库尾零，首轮扫读成本偏高；
  聊天证据宜默认折叠，状态使用中文业务标签，展示数值应去除无意义尾零但不得改变值。
- “产品范围匹配”不等于获得认证或商业可售；Demo 结果需要在结果标题和摘要层同时
  保留这一边界，而不是只依赖页面其他位置的免责声明。

## 4. 历史法规语义（本轮实际采纳）

`asOf` 现在用于派生查询时状态 `statusAtAsOf`，同时保留持久记录的生命周期状态
`recordStatus`（国家详情兼容 DTO 中的原字段名为 `status`）：

1. `[effectiveFrom,effectiveTo)` 覆盖 `asOf` 时，`statusAtAsOf=effective`；因此
   `recordStatus=superseded` 的记录仍可在其历史有效期内返回，并明确表示“当时有效、
   现已取代”。superseded 记录必须有非空 `effectiveTo` 才能证明这个闭合区间。
2. 未来生效记录只有在 `adoptedOn` 已知且不晚于 `asOf` 时，才可派生为
   `statusAtAsOf=adopted`。采纳日缺失或 superseded 终止日缺失的异常记录仍保留在
   数据库中供数据治理，但从查询日 effective/adopted 集合中 fail-closed 排除。
3. `proposed` 永远不能派生为 effective，也不能进入 product-fit 的有效法规集合。
4. 比较、产品适配、AI citation 和国家详情必须沿用同一派生语义，不能各自按当前
   `recordStatus` 猜测历史状态。

这不是完整双时态模型。系统仍没有独立的 `knownAsOf` / transaction-time 轴，不能回答
“系统在历史某天当时知道什么”，也不能完整重演后来更正、补录或撤回之前的知识快照。
`verifiedAt` 是来源核验时间，不是 `knownAsOf` 的替代品。

本轮实现通过 `pnpm lint`、`pnpm typecheck`、856 条 Vitest、生产构建和默认完整
Playwright（60 passed / 6 skipped）；作品集 Demo 专属点名产品用例在桌面与移动端另有
2 passed。浏览器走查确认“演示匹配”边界、历史状态标签及国家详情到预填对话的上下文
链路。自动化与浏览器检查证明实现回归，不构成现实用户 KPI 或法规专家验收。

## 5. 如何使用这份评估

本文件只证明项目对三种代表视角做过一次结构化的内部模拟和问题闭环。求职材料可以
描述“通过三角色模拟发现并修复历史时态缺陷”，但不能写成“完成 3 位用户访谈”、
“通过法规专家验收”或“试点效率提升”。真实客户交付证据仍需单独招募用户、取得
知情反馈并预先定义任务和 KPI。
