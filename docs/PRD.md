# 全球柴油机法规与市场分析平台 PRD

## 1. 文档状态

- 阶段：求职作品集 MVP
- 状态：Draft（作品定位与业务场景已确认）
- 目标读者：产品负责人、法规专家、销售负责人、数据运营、研发与测试
- 本文不授权开始业务功能实现；进入实现前需完成第 13 节的 MVP 决策门

## 2. 产品背景

柴油机销售人员在进行国家选择、产品匹配和客户沟通时，需要同时判断法规是否生效、适用场景与功率范围、产品认证覆盖、市场规模以及证据的新鲜度。相关事实通常分散在法规原文、政府公告、产品手册和行业报告中，且 proposed、adopted、effective、superseded 等状态容易被混淆。

本产品以世界地图为主要入口，将可核验的结构化事实与可追溯的原文证据结合，并提供一个只能通过确定性工具获取事实的 AI 营销分析助手。它是个人求职作品，
用于展示全栈工程、数据建模、AI 工具调用、证据边界和产品设计能力，不代表潍柴或
任何其他公司的官方产品，也不提供法律意见。

## 3. 目标用户

### 3.1 作品展示对象与模拟用户

- 招聘方与面试官：快速理解项目范围、工程质量、数据可信度和 AI 安全边界。

- 海外柴油机销售：筛选市场、核对法规、匹配产品并准备客户沟通。
- 区域销售经理：比较国家机会、风险与团队优先级。
- 产品经理和应用工程师：核对产品参数、认证与特定工况的适配关系。

### 3.2 支持用户

- 法规/合规专家：录入或审核法规、状态、限值和证据。
- 数据运营：维护市场指标、来源、发布日期和核验日期。
- 系统管理员：维护访问控制、数据导入和审计。

MVP 是否包含面向法规专家的数据后台尚未决定；默认先采用受控种子/导入脚本，而不是在 UI 中编辑。

## 4. 产品目标与成功标准

### 4.1 目标

1. 用户能从地图进入国家详情，并通过可分享 URL 复现当前国家。
2. 用户能按应用范围、功率和日期查到正确的法规要求，且始终看到状态、来源和最近核验时间。
3. 用户能查看口径明确的市场指标及其统计期间、单位和来源。
4. 用户能获得由确定性规则计算的产品适配结果，并看到通过、缺口或未知的原因。
5. AI 助手只基于工具返回的结构化事实和检索证据进行比较、推荐、风险提示与销售策略说明。
6. 无数据、证据过期、适用范围不匹配和 proposed 法规均被显式提示。

### 4.2 MVP 验收指标

- 所有国家详情 URL 使用 ISO 3166-1 alpha-3 代码，并可直接打开。
- 目标测试数据集中的法规状态、有效期边界和功率边界查询全部通过自动化测试。
- AI 法规回答中的可核验事实均可关联至少一个来源；无来源时明确标注“证据不足”，不生成肯定结论。
- product-fit 结果由同一输入产生稳定、可复现的结果，并返回规则版本与证据。
- 桌面端可 hover 预览，键盘与触摸设备可通过 click/focus 获取同等关键信息。
- 关键页面具备 loading、empty、no-data 和 error 状态。
- 未授权的浏览器请求不能获得服务端数据库密钥或模型 API Key。

业务 KPI（例如检索耗时下降、销售线索转化率提升）需要在试点用户和基线流程确定后设置，不在当前规划中伪造目标值。

## 5. MVP 使用场景

### 5.1 地图探索

1. 用户打开世界地图。
2. 指针设备 hover 国家时显示名称、数据覆盖状态、主要法规状态和最近核验日期的轻量预览。
3. 用户 click 国家后进入 `/countries/{ISO3}`。
4. 触摸设备不依赖 hover，第一次点击即可选择并显示国家信息。
5. 无数据国家显示明确的 no-data 状态，不以空白或错误代替。

### 5.2 法规查询

1. 用户在国家详情选择应用范围、功率和基准日期。
2. 系统查询适用法规、要求和污染物限值。
3. 系统显示法规名称、状态、适用条件、生效/失效日期、来源、发布日期和最近核验时间。
4. proposed 法规与当前 effective 法规分区显示，不将 proposed 当作当前要求。

### 5.3 市场与产品适配

1. 用户查看指标定义、值、单位、统计期间、方法说明和来源。
2. 用户选择产品或产品配置。
3. 系统以确定性代码检查功率、应用范围、法规/认证和有效期。
4. 结果为 `fit`、`partial_fit`、`not_fit` 或 `unknown`，并逐项列出理由与证据；营销评分如存在，也由确定性代码计算。

### 5.4 AI 营销分析

1. 用户提出“比较两个市场”“推荐可销售产品”“提示法规风险”或“给出销售策略”等问题。
2. 单个 Agent 选择一个或多个只读工具。
3. 工具使用 Zod 校验参数，查询结构化数据库或按元数据过滤知识库。
4. Agent 仅依据工具结果组织回答；缺少事实时说明缺口。
5. UI 优先渲染比较卡片、产品适配卡片、风险卡片和来源列表，而不是只显示 Markdown 长文。

## 6. MVP 功能范围

### 6.1 国家与地图

- 世界 GeoJSON 静态边界，以 `ISO3` 属性连接数据库。
- 国家基础信息：名称、ISO2/ISO3、区域、子区域和可配置的基础字段。
- 数据覆盖状态和最近核验日期。
- hover、focus 与 click 交互。
- 国家详情可分享 URL；筛选器是否进入 query string 由实现阶段确定，建议纳入以支持完整复现。

### 6.2 法规

- 明确的 `proposed`、`adopted`、`effective`、`superseded` 状态。
- 作品主线使用卡车动力、客车动力、工程机械动力、农业装备动力四个业务场景。
  数据模型保留法规层面的 on-road/non-road 父级分类，但 UI、产品与认证必须能
  区分卡车和客车，不能只保存一个过宽的 on-road 值。
- 法规、要求、功率区间、污染物限值、单位、测试循环/测量口径和有效期。
- 国家与区域性司法辖区映射，以支持类似跨国法规体系。
- 结构化记录与来源文档的可追溯关联。

### 6.3 市场

- 经过定义的少量核心指标，不接受没有指标定义或统计期间的裸数值。
- 观察值包含单位、币种（若适用）、期间、发布日期、方法、来源和最近核验时间。
- 国家间比较前进行单位与口径兼容性检查；不可比时明确提示。

### 6.4 产品与适配

- 公司、产品系列、可销售配置、功率范围、应用范围和产品参数。
- 产品认证及其法规、应用范围、功率范围和有效期。
- 确定性 product-fit 与可选的确定性营销评分。
- 不确定信息不得自动推断为适配。

### 6.5 知识库与 AI

- 法规原文、公告、产品手册和行业报告的文档元数据与对象存储引用。
- 文档分块保留来源、标题层级、页码/章节、司法辖区、国家、应用范围和有效期。
- 关键词与向量混合检索，必须先做元数据过滤。
- 单 Agent，多只读确定性工具；所有参数和返回值均使用 Zod schema。
- 流式回答可以使用，但引用与结构化工具结果不能被流式文本覆盖或改写。

## 7. 建议的确定性 AI 工具

MVP 工具集合保持小而明确：

| 工具 | 作用 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| `getCountryProfile` | 获取国家及覆盖状态 | ISO3 | 基础信息、覆盖度、核验时间 |
| `findApplicableRegulations` | 查找指定日期/范围/功率的法规 | ISO3、日期、应用范围、功率 | 法规、状态、要求、限值、来源 |
| `compareMarkets` | 比较同口径市场指标 | ISO3 列表、指标、期间 | 规范化值、不可比警告、来源 |
| `evaluateProductFit` | 计算产品适配 | 产品配置、ISO3、日期、范围、功率 | 确定性结论、规则版本、缺口、证据 |
| `searchEvidence` | 检索解释性原文 | 查询、司法辖区/国家、范围、日期 | 可引用 chunks、locator、有效期警告 |

工具不得接受任意 SQL。LLM 不直接访问 Drizzle、Supabase 或对象存储。

## 8. 核心业务规则

1. `proposed` 只表示拟议要求，不能作为当前合规结论。
2. 法规状态与有效期是不同维度；查询需要同时判断。
3. 功率区间统一存储为 kW，采用下界包含、上界不包含 `[min, max)`；原文单位和值另行保留用于审计。
4. 法律限值原始单位不得在没有明确换算规则时被覆盖。
5. 市场指标只有在指标定义、单位、统计期间和方法兼容时才可直接比较。
6. 产品覆盖功率和应用范围不等于拥有法规认证；适配必须分别检查。
7. 缺少认证、来源或有效期时返回 `unknown` 或 `partial_fit`，不能乐观推断。
8. 每条法规要求、限值、市场观察值和认证都需带来源关系与 `verified_at`。
9. 知识库片段与问题日期或应用范围冲突时，只能作为带警告的背景，不得支持无警告结论。
10. 营销评分由版本化的确定性规则计算，LLM 只能解释。

## 9. 非功能要求

### 9.1 安全

- 数据库 service role key、模型 key 和对象存储签名能力仅存在于服务端。
- 环境变量按 server-only 与可公开变量分组；公开变量仅允许地图样式等非敏感配置。
- 所有路由输入、工具输入、导入数据和环境配置均经 Zod 校验。
- 查询使用 Drizzle 参数化能力；不得拼接用户 SQL。
- 产品、市场和内部策略数据是否允许公开访问必须在部署前确定。

### 9.2 可访问性与响应式

- 使用语义 HTML、可见 focus、键盘操作和合理的颜色对比度。
- hover 信息必须能通过 focus/click 获取。
- 小屏以国家详情面板/抽屉替代依赖精细指针的交互。

### 9.3 性能

- 不将大型世界几何放入 React 状态；地图加载静态 GeoJSON。
- 国家摘要与详情分层查询；地图首屏不加载完整法规和文档内容。
- 目标性能预算在获得部署区域、瓦片服务和数据量后确定。

### 9.4 可观测性与审计

- 记录 AI 工具名、校验后的参数摘要、返回事实/来源 ID、规则版本、耗时和错误。
- 不在日志中记录密钥、完整受版权保护文档或不必要的用户敏感内容。
- 结构化数据更新需保留创建/更新时间和核验责任信息。

## 10. 明确不在 MVP 实现的内容

- 多 Agent 编排、Agent 间委派和自治数据写入。
- 为全球国家建立基础目录和覆盖状态，但不承诺为每个国家补齐全部法规、限值和
  历史版本。
- AI 自动判定法律合规或替代法规专家签字。
- AI 自动修改法规、市场、产品或认证数据。
- 完整 CMS、法规审批工作流和可视化 ETL 编排器。
- 自动抓取所有政府网站、付费报告或绕过许可限制。
- 实时市场预测、动态定价、CRM 线索管理和邮件/日历集成。
- 路线规划、经销商空间分析等 PostGIS 空间计算。
- 离线地图、原生移动应用和完整国际化。
- 复杂 RBAC、SSO 或外部客户门户，除非访问模型决策将其提升为上线阻塞项。
- 在代表性语料与检索评估完成前建立生产向量索引。
- 对不同法域的所有单位、测试循环做自动法律等价换算。

## 11. 假设

- MVP 是公开展示的个人求职作品；公开页面只使用获准再分发的公开来源，不包含
  真实公司的机密产品、市场或客户数据。
- 国家采用分层覆盖：全球目录提供基础信息和明确的 `no_data/planned/partial/verified`
  状态；主流国家提供摘要；重点国家提供法规、产品适配和来源的深度纵向切片。
- 首批深度样板为中国、美国、德国/欧盟、印度、巴西，随后扩展到日本、韩国、
  墨西哥、土耳其和澳大利亚。
- 用户查询中的“日期”默认指业务适用日期；系统另存最近核验时间。
- 法规与产品专家会提供或审核种子数据，研发不负责判断原文的法律含义。
- MapLibre 的底图样式、瓦片和世界边界数据具备允许部署与再分发的许可。
- Supabase PostgreSQL 同时启用 pgvector；PostGIS 仅安装/预留，不用于普通国家点击查询。
- 文档二进制文件放对象存储，元数据、chunks 和 embeddings 放 PostgreSQL。
- MVP 可使用单一界面语言；具体是中文、英文或中英双语仍待决定。

## 12. 仍需确认的问题

| 主题 | 待确认内容 | 不确认的影响 |
| --- | --- | --- |
| 数据切片 | 已确认分层国家覆盖和四类动力场景；仍需逐国冻结法规年份、来源和产品系列 | 无法定义真实 fixture |
| 访问模型 | 公开只读作品已确认；后台登录与托管平台仍待决定 | 阻塞管理后台公开部署 |
| 数据责任 | 谁录入、谁核验、核验 SLA、多长时间算 stale | 无法定义运营流程和新鲜度告警 |
| 模型供应商 | 文本生成模型、Embedding 模型与维度、数据处理区域 | 阻塞 AI 适配器和向量列迁移 |
| 数据许可 | 地图、法规原文、行业报告、产品手册的存储/展示权限 | 存在版权和合规风险 |
| 指标口径 | MVP 市场指标及定义、单位、频率和来源 | 无法实现可靠市场比较 |
| 产品规则 | 产品主数据来源、认证粒度、fit 与评分规则 | 无法实现可复现推荐 |
| 司法辖区 | 区域法规如何覆盖成员国以及历史成员关系 | 影响适用法规查询 |
| 语言 | UI、检索、文档 OCR/翻译和回答语言 | 影响 chunking、Embedding 与测试 |
| 部署 | Supabase/Vercel 区域、数据驻留、日志保留 | 影响性能与合规 |

## 13. MVP 决策门

开始业务代码前至少冻结以下内容：

1. 首批深度样板采用中国、美国、德国/欧盟、印度、巴西；场景采用卡车、客车、
   工程机械、农业装备。
2. 每个范围的代表性法规和一组有效期/功率边界测试样例。
3. 2–3 个市场指标定义。
4. 5–10 个产品配置及其认证证据。
5. 访问模型与可公开/机密数据分类。
6. 生成模型、Embedding 模型、维度与数据处理区域。
7. 地图、法规文档和行业报告许可结论。
8. product-fit 规则负责人和核验人。

## 14. 发布定义

MVP 不是“拥有地图和聊天框”即完成。只有当选定纵向切片的数据可追溯、边界查询通过、产品适配可复现、AI 无工具事实被阻止，且安全与可访问性检查通过时，才可发布给试点用户。
